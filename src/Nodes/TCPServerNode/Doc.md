# TCP Server

## 1. 节点说明

TCP 服务端节点，在本机指定地址和端口监听，接受客户端连接并收发数据。适合作为中控被多台客户端连接，或接收局域网内设备的 TCP 上报。

## 2. 端口说明

| 方向 | 默认数量 | 可编辑 | 最小 | 最大 | 新增端口类型 | 末端口差异 |
|------|----------|--------|------|------|--------------|------------|
| 输入 | 4 | 否 | 4 | 4 | — | 末端口为 TRIGGER（发送触发） |
| 输出 | 4 | 否 | 4 | 4 | — | 末端口为 HEX（十六进制） |

> 本表对应 .flow 中该节点的 `input-count` / `output-count` / `port-editable` 三个字段：
> AI 搭图时连接索引不能超过当前端口数，可编辑节点的取值范围由"最小/最大"给出。



### 输入

| 端口 | 名称 | 说明 |
|------|------|------|
| 0 | HOST | 设置监听地址（如 `0.0.0.0` 表示所有网卡） |
| 1 | PORT | 设置监听端口 |
| 2 | VALUE | 设置发送内容并立即发送给已连接客户端 |
| 3 | TRIGGER | 输入为 `true` 时，按当前界面内容发送 |

### 输出

| 端口 | 名称 | 说明 |
|------|------|------|
| 0 | RESULT | 完整接收消息（VariableData） |
| 1 | HOST | 发送方 IP 地址 |
| 2 | VALUE | 接收到的文本内容 |
| 3 | HEX | 接收数据的十六进制字符串 |

## 3. 界面与属性

节点控件面板（`WidgetEmbeddable=false`，显示在右侧属性面板，不嵌入节点体）：

| 控件 | 说明 |
|------|------|
| host（行编辑框） | 监听地址，界面默认 `0.0.0.0`；编辑完成即重启监听 |
| Port（数字拖动框） | 监听端口，界面默认 `2001`；变更即重启监听 |
| value（行编辑框） | 要广播的文本；编辑完成立即按当前格式发送 |
| Format（下拉框） | 发送编码：HEX / UTF-8 / ASCII |
| Send（按钮） | 向所有已连接客户端广播发送 |

节点公开 3 个 `Q_PROPERTY`：

| 属性 | 类型 | 说明 |
|------|------|------|
| `host` | QString | 监听地址（变更即重启监听） |
| `port` | int | 监听端口（变更即重启监听） |
| `value` | QString | 广播内容（赋值即发送） |

## 4. 外部控制（OSC 地址）

地址前缀：`/dataflow/{别名}/{节点ID}/…`

| 地址 | 方向 | 说明 |
|------|------|------|
| `/host` | 可写（命令） | 字符串，改监听地址并立即重启监听 |
| `/port` | 可写（命令） | 整型，改监听端口并立即重启监听 |
| `/value` | 可写（命令） | 字符串，设置广播内容并**立即发送** |
| `/send` | 可写（命令） | 触发一次广播；模型回发 `/send` true→false 脉冲状态反馈 |

`host`/`port`/`value`/`send` 均通过 `registerExternalBinding` 注册（绑定界面控件）并订阅 Command 事件。

## 5. 行为细节

- **线程模型**：QTcpServer 与全部客户端 socket 在独立工作线程中创建与收发（TcpWorker），模型层通过队列信号交互。
- **重启语义**：`host`/`port` 任一变更即「关闭服务器与所有客户端连接 → 按新地址重建监听」，原已连接客户端会被断开。
- **初始监听地址注意**：节点创建后实际以设备层默认参数监听 `127.0.0.1:2001`；界面显示的 `0.0.0.0` 只是控件初始文本，**未自动生效**——需修改一次 host/port（界面、端口输入或 OSC）才会按显示值重启监听。
- **发送**：按 Format 编码（HEX=`QByteArray::fromHex`、UTF-8、ASCII/Latin1）后写给**所有**已连接客户端；发送动作伴随 `/send` true→false 脉冲反馈。
- **VALUE 自动发送**：`value` 属性赋值即触发广播（不去重）——VALUE 端口、`/value`、界面编辑完成都会立即发出。
- **TRIGGER**：输入 `true` 直接按当前 `value` 广播（不重取界面文本）。
- **接收**：每条消息打包为 QVariantMap `{host（发送方地址）, hex, utf-8, ascii, default（原始字节）}` 推给 RESULT，同时刷新 HOST/VALUE/HEX 三路输出。
- **客户端管理**：新连接自动加入列表，断开自动移除；发送不检查连接状态（失效 socket 由 write 失败/断开信号清理）。
- **端口连接策略**：所有输入、输出端口均可连多路（Many/Many）。
- **持久化**：`values.Port`、`values.Host`、`values.Value`、`values.Format`（键名首字母大写）；加载后恢复并触发监听重启。

## 6. 使用说明与典型接法

1. 设置 **host** 与 **port**；修改后会自动重启监听。
2. 客户端连接后，收到的数据从 **RESULT**、**HOST**、**VALUE**、**HEX** 输出。
3. 填写 **value** 后点 **Send**，或从 **VALUE** / **TRIGGER** 端口触发发送。
4. 也可通过输入端口动态改监听地址、端口或发送内容。

## 7. 示例

- **灯光控台回传**：客户端连上后，收到的 JSON 从 **VALUE** 连到解析节点。
- **广播指令**：**value** 填 `{"cmd":"allOff"}`，**Send** 或 **TRIGGER** 一次，所有已连接客户端同时收到。
- **远程改端口**：OSC 命令写 `/dataflow/Main/5/port` 为 `9000`，服务在新端口监听。
