# WebSocket Server

## 1. 节点说明

WebSocket 服务端节点，在指定端口启动 WS 服务，接受浏览器或客户端连接，支持文本与二进制消息的双向收发。设备层为独立线程 + QWebSocketServer，端口变更即断开所有客户端并重建监听。适合 Web 面板、移动端与节点图实时通信。

接收消息打包为多键 VariableData（utf-8 / ascii / hex / host）；发送按界面编码广播给所有已连接客户端。

## 2. 端口说明

| 方向 | 默认数量 | 可编辑 | 最小 | 最大 | 新增端口类型 | 末端口差异 |
|------|----------|--------|------|------|--------------|------------|
| 输入 | 3 | 否 | 3 | 3 | — | 末端口为 TRIGGER（发送触发） |
| 输出 | 4 | 否 | 4 | 4 | — | 末端口为 HEX（十六进制） |

> 本表对应 .flow 中该节点的 `input-count` / `output-count` / `port-editable` 三个字段：
> AI 搭图时连接索引不能超过当前端口数，可编辑节点的取值范围由"最小/最大"给出。

### 输入

| 端口 | 名称 | 数据类型 | 说明 |
|------|------|----------|------|
| 0 | PORT | VariableData | 整数：设置监听端口并重启服务 |
| 1 | VALUE | VariableData | 字符串：设置发送内容并**立即广播** |
| 2 | TRIGGER | VariableData | 收到任意数据即按当前内容广播（不检查真假） |

### 输出

| 端口 | 名称 | 数据类型 | 说明 |
|------|------|----------|------|
| 0 | RESULT | VariableData | 接收消息完整键值表（见「行为细节」） |
| 1 | HOST | VariableData | 消息来源客户端 IP |
| 2 | VALUE | VariableData | 接收内容（`default` 键值，原始字节） |
| 3 | HEX | VariableData | 接收数据十六进制字符串 |

收到消息时四个输出端口同时推送更新。

## 3. 界面与属性

控件面板（`WidgetEmbeddable=false`，显示在右侧属性面板，不嵌入节点体）：

| 控件 | 说明 |
|------|------|
| Port 数字框 | 监听端口（0–65536），**界面初始显示 2003，节点实际默认监听 8888**；修改即重启服务 |
| Value 输入框 | 广播内容；编辑完成即广播 |
| Message Type 下拉框 | TEXT / BINARY（**注意源码映射写反**，见「行为细节」） |
| Format 下拉框 | HEX / UTF-8 / ASCII |
| Send 按钮 | 向所有已连接客户端广播 |

公开属性（Q_PROPERTY）：

| 属性 | 类型 | 说明 |
|------|------|------|
| `port` | int | 监听端口，变更即重启服务 |
| `value` | string | 广播内容，赋值即广播 |

## 4. 外部控制（OSC 地址）

地址前缀：`/dataflow/{别名}/{节点ID}/…`

| 地址 | 方向 | 说明 |
|------|------|------|
| `/port` | 可写 | 设置监听端口并重启服务（payload 转整数） |
| `/value` | 可写 | 设置广播内容并**立即广播**（赋值即发） |
| `/send` | 可写 | 触发一次广播（任意 payload），随后反馈瞬时 true→false |

## 5. 行为细节

- **监听启动**：设备层构造即在 **8888** 端口监听（`0.0.0.0`）；界面初始显示 2003，属源码不一致——新建节点后需修改一次端口（或由工程 load 触发 `setPort`）才与显示一致；端口变更先关闭旧服务与全部客户端连接再按新端口重建监听。
- **发送编码**：Format 决定字节内容——HEX（字符串按 hex 解码）/ UTF-8 / ASCII（Latin1）；Message Type 决定帧类型，**但源码映射写反**：选 TEXT（索引 0）实际发 `sendBinaryMessage`（二进制帧），选 BINARY（索引 1）实际发 `sendTextMessage`（文本帧），接收端按此对应解析。
- **赋值即发**：`/value` 属性变化即广播（端口 1、OSC 写、界面编辑完成都一样）；TRIGGER 仅作触发不读取值。
- **发送反馈**：每次广播通过 `/send` 地址推送瞬时 true→false 脉冲。
- **接收打包**：任一客户端发来消息（文本帧转 UTF-8 字节、二进制帧原样）输出 VariableData 键值表：`hex`、`host`（对端 IP）、`utf-8`、`ascii`、`default`（原始字节）。多个客户端的消息都会输出，以最新一条为准。
- **客户端管理**：连接建立加入广播列表，断开自动移除；广播只发给处于已连接状态的客户端。
- **持久化**：`values` 子对象含 `Port`、`Value`、`Format`、`MessageType`（下拉索引）；加载时按保存端口重启监听（保存端口恰为 8888 时因与默认值相同跳过重启，实际仍在监听 8888，行为一致）。
- **析构**：停止服务并断开所有客户端，等待设备线程退出。

## 6. 使用说明与典型接法

1. 设置 **port**（注意先改一次让界面与实际一致）；客户端连 `ws://本机IP:端口`。
2. 客户端消息从 **RESULT** / **HOST** / **VALUE** / **HEX** 输出（用 Extract 取键）。
3. 填写 **value**，选择 Format，点 **Send** 或从输入端口 / OSC 触发广播。
4. 工程保存端口、广播内容与格式设置。

## 7. 示例

- **网页控台**：前端 `ws://本机IP:2003` 连接，按钮发 JSON，节点 **RESULT** 驱动场景切换。
- **二进制协议**：**Format** 选 HEX，发送十六进制固件升级数据包（注意 Message Type 实际帧类型与标签相反，接收端按二进制/文本帧相应解析）。
- **远程改文案**：OSC 写 `/value` 即广播（或写 `/value` 后命令 `/send`），所有已连接客户端同步收到新文字。
