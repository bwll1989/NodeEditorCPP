# Audio Device Out

## 1. 节点说明

将多路 AudioData 混音并输出到本机音频设备（声卡）。按全局时间戳从环形缓冲取帧，连接后自动开始播放。

## 2. 端口说明

| 方向 | 默认数量 | 可编辑 | 最小 | 最大 | 新增端口类型 | 末端口差异 |
|------|----------|--------|------|------|--------------|------------|
| 输入 | 2 | 是 | 1 | 不限 | AudioData | 无 |
| 输出 | 0 | 否 | 0 | 0 | — | 无 |

> 本表对应 .flow 中该节点的 `input-count` / `output-count` / `port-editable` 三个字段：
> AI 搭图时连接索引不能超过当前端口数，可编辑节点的取值范围由"最小/最大"给出。



### 输入

- **输入 0、输入 1…**（AudioData）：待输出的声道。**端口索引即设备声道号**：输入 0 写入设备声道 1，输入 1 写入设备声道 2，依此类推。
- 连接有效音频连接后自动开始播放；断开连接后该声道静音（输出缓冲每回调清零）。
- 端口索引超出设备最大输出声道数时该路被跳过，不出声也不报错。

### 输出

无。

## 3. 界面与属性

本节点无节点内嵌界面（`WidgetEmbeddable = false`），以下控件显示在右侧属性面板：

- **驱动类型**（下拉框）：PortAudio 主机 API 筛选（如 MME、DirectSound、WASAPI），切换后设备列表联动刷新。
- **设备选择**（下拉框）：输出设备列表，默认系统默认输出设备。

持久化：`save()` 保存 `selectedDeviceIndex/Text/Data` 与 `selectedDriverIndex/Text/Data`；`load()` 先恢复驱动（设备列表联动），延迟 100ms 后按设备索引匹配恢复设备选择。

## 4. 外部控制（OSC 地址）

本节点未注册任何专属 OSC 地址（源码中无 `Q_PROPERTY` 外部属性，也无 `registerExternalBinding` 调用），端口增删由节点图内部完成。

地址前缀：`/dataflow/{别名}/{节点ID}/…`。若节点定义了公开 Q_PROPERTY，框架会自动为其生成默认属性地址；本节点当前无此类属性。

## 5. 行为细节

- **时钟与取帧**：PortAudio 回调按全局时间戳（`TimestampGenerator` 帧计数）从各输入端口的 `AudioTimestampRingQueue` 取帧；缓冲块大小 = `TimestampGenerator::getSamplesPerFrame(48000)`。
- **追赶策略**：某端口上次消费时间戳与当前全局时间戳相同（说明本回调周期无新帧）时，尝试取 `lastTs + 1` 的帧，最多追赶一帧，避免重复播放同一帧。
- **声道映射**：回调内将端口 i 的帧交错写入输出缓冲的第 i 个声道（`outPtr = output + portIndex`，步进 `deviceChannels`）；输出缓冲每回调先清零，未连接的声道静音。
- **自动启停**：首个有效音频连接建立时自动 `startAudioOutput()`；析构时停止并关闭 PortAudio 流。

## 6. 使用说明与典型接法

1. 在属性面板选择驱动类型与输出设备（声道数由设备决定）。
2. 将解码器、麦克风、交叉淡化的 AudioData 输出按声道顺序接入输入端口（端口序号 = 声道序号）。
3. 多声道扩展：需要多于 2 个声道时直接继续连接，端口会自动增加（上限受设备声道数约束，超出的端口不出声）。
4. 连接有效音频后自动开始播放，无需手动触发。

## 7. 示例

```
Video Decoder CH1 ──┐
Video Decoder CH2 ──┤ Audio Device Out ──→ 声卡（立体声输出）
Audio Device In  ───┘（第三路需设备支持 ≥3 声道）
```
