# Object Track

## 1. 节点说明

> ⚠️ **版本要求**：本节点为 **Advance（进阶版）** 功能，需有效授权后才能加载使用。

在画面里点选物体，用分割结果作为视觉提示，再在后续画面中跟踪这些物体。支持多个 ID，每个 ID 可以点选多次取样。

选择和检测分成两段：点选时只分割并保存样本，不跟踪；点「开始检测」之后才跟踪，检测过程中不能再点选。

模型文件：

- `./plugins/Models/mobile-sam-click.onnx`：点击分割
- `./plugins/Models/yoloe-prompt.onnx`：把样本编成提示向量
- `./plugins/Models/yoloe-detect.onnx`：在画面中匹配这些向量

样本保存在文档目录下的 `Flow/Cache/ObjectTrackRefs/`。工程里只记录文件名，打开时再拼到这个目录。每张是带透明通道的 PNG，透明通道是物体区域。输入画面长边超过 1280 时会先缩小，`pixel` 对应缩小后的画面。

## 2. 端口说明

| 方向 | 默认数量 | 可编辑 | 最小 | 最大 | 新增端口类型 | 末端口差异 |
|------|----------|--------|------|------|--------------|------------|
| 输入 | 2 | 否 | 2 | 2 | — | 末端口为 ENABLE（启停） |
| 输出 | 2 | 否 | 2 | 2 | — | 无 |

> 本表对应 .flow 中该节点的 `input-count` / `output-count` / `port-editable` 三个字段：
> AI 搭图时连接索引不能超过当前端口数，可编辑节点的取值范围由"最小/最大"给出。



### 输入

| 端口 | 数据类型 | 说明 |
|------|----------|------|
| IMAGE | ImageData | 实时画面。预览和跟踪都用这一路 |
| ENABLE | VariableData | 布尔启停。`true` 开始检测，`false` 停止。与「开始检测」按钮、OSC `/enable` 同步 |

没有样本时，ENABLE 置为 `true` 不会开始检测。

### 输出

| 端口 | 数据类型 | 说明 |
|------|----------|------|
| IMAGE 0 | ImageData | 画有跟踪框的画面。关闭「绘制跟踪框」后不刷新这一路 |
| RESULT | VariableData | 各目标是否在画面中，以及位置。见下文 |

## 3. 界面与属性

控件面板（`WidgetEmbeddable=false`，显示在右侧属性面板，不嵌入节点体）：

- **预览**：显示输入画面。未开始检测时，点击画面分割并保存当前 ID 的一次取样
- **目标 ID**：留空时按 1、2、3… 自动编号。同一 ID 可多次点击，列表显示「取样次数」
- **删除选中**：删掉列表中选中的 ID
- **相似度阈值**：低于该值的匹配被丢弃，默认 `0.25`，范围 0–1
- **最大帧率 (FPS)**：检测频率，默认 `15`，范围 1–30
- **丢失保持 (帧)**：暂时丢失后继续保留位置的帧数，默认 `8`，范围 0–60。这段时间不画框
- **绘制跟踪框**：关闭后只更新 RESULT
- **开始检测 / 停止检测**：选择完成后手动开始。工程会保存该状态，下次打开时恢复

检测过程中预览不再接受点击。停止检测后可以继续点选。

## 4. 外部控制（OSC 地址）

地址前缀：`/dataflow/{别名}/{节点ID}/…`

| 地址 | 方向 | 说明 |
|------|------|------|
| `/enable` | 读写 | 开始或停止检测（bool；无样本或分割进行中时写入被拒绝，界面提示原因） |
| `/confidence` | 读写 | 相似度阈值（自动收敛到 0–1，绑定阈值拖动框） |

> `maxFps`、`drawOverlay`、`holdFrames` 三个属性无 OSC 绑定，只能在界面或 `.flow` 工程中设置。

## 5. 行为细节

**RESULT 数据结构**：`default` 是以目标 ID 为键的对象，没有额外的列表序号。

```json
{
  "default": {
    "phone": {
      "confidence": 0.386,
      "position": [0.7426, 0.7958],
      "pixel": [742, 796],
      "present": false
    }
  }
}
```

| 字段 | 说明 |
|------|------|
| `confidence` | 相似度，0–1，保留 4 位小数 |
| `position` | 归一化中心 `[x, y]`，范围 0–1，保留 4 位小数 |
| `pixel` | 中心像素 `[x, y]`，相对本节点输出画面的整数坐标 |
| `present` | 这一帧匹配到该目标时为 `true` |

暂时丢失时 `present` 为 `false`，`position` 和 `pixel` 保持最后一次真实检测到的位置，不画跟踪框。从未匹配过的目标保持 `[0, 0]`。

其他行为：

- **调度**：订阅 TimestampGenerator 帧时钟刷新预览并调度推理，按 `maxFps` 节流（自动收敛到 1–30）；推理进行中时合并为新帧，不积压。
- **启动前置检查**：开始检测前必须已有样本且分割流程已结束；否则拒绝启动并提示「请先选择对象」/「正在分割，请稍候再开始检测」。
- **停止清理**：停止检测时丢弃挂起帧、取消推理、清空跟踪状态与输出图像缓冲，RESULT 复位为空；IMAGE 输入断开同样清空输出。
- **参数边界**：相似度阈值收敛到 0–1；丢失保持取整并收敛到 0–60 帧；修改阈值会立即重新推理当前帧。
- **共享模型**：同一工程中的多个 Object Track 节点共享一套 ONNX 模型实例（引用计数管理，最后一个释放），推理排队执行。
- **持久化**：`save()` 将 `confidence`、`enabled`、`maxFps`、`drawOverlay`、`holdFrames` 与 `targets`（每个目标含 `id` 与样本图片相对路径数组 `images`）写入 `values.*`；样本 PNG 存于 `Flow/Cache/ObjectTrackRefs/`，工程只记文件名，加载时再从该目录解析。

## 6. 使用说明与典型接法

1. 把图像源接到 IMAGE。
2. 在预览上点击要跟踪的物体。需要多个物体时，换一个 ID 再点。
3. 点「开始检测」，或向 ENABLE / `/enable` 送 `true`。
4. 用 RESULT 读取每个 ID 的 `present` 和 `position`。需要像素坐标时读 `pixel`。
5. 要改样本时先停止检测，再点击或删除。

同一图里可以放多个本节点，它们共用一套模型，推理排队执行。

## 7. 示例

Camera → **Object Track**（点选演员，ID 设为 `host`）→ Condition（`present` 为真时）→ 切换机位。
