# USR-IO808

## 1. 节点说明

> ⚠️ **版本要求**：本节点为 **Advance（进阶版）** 功能，需有效授权后才能加载使用。

通过 **Modbus TCP** 控制有人 USR-IO808 等 8 路开关量模块：写入数字输出（DO），读取数字输入（DI）。DO 变化时一次写入全部线圈；连接建立后会将当前 DO 设置同步到设备，并定时轮询 DI/DO。

## 2. 端口说明

| 方向 | 默认数量 | 可编辑 | 最小 | 最大 | 新增端口类型 | 末端口差异 |
|------|----------|--------|------|------|--------------|------------|
| 输入 | 8 | 否 | 8 | 8 | — | 无 |
| 输出 | 8 | 否 | 8 | 8 | — | 无 |

> 本表对应 .flow 中该节点的 `input-count` / `output-count` / `port-editable` 三个字段：
> AI 搭图时连接索引不能超过当前端口数，可编辑节点的取值范围由"最小/最大"给出。



### 输入

| 端口 | 类型 | 说明 |
|------|------|------|
| DO 0～7 | VariableData | 布尔值，设置对应数字输出通断 |

### 输出

| 端口 | 类型 | 说明 |
|------|------|------|
| DI 0～7 | VariableData | 布尔值，对应当前数字输入状态 |

## 3. 界面与属性

节点控件面板（`WidgetEmbeddable=false`，显示在右侧属性面板，不嵌入节点体）：

| 控件 | 说明 |
|------|------|
| 主机（行编辑框） | 模块 IP，默认 `127.0.0.1`；变更即断开重连 |
| 端口（数字拖动框） | Modbus TCP 端口，默认 `502`；变更即断开重连 |
| 从站 ID（数字拖动框） | 默认 `1` |
| 连接状态 | TCP 是否就绪 |
| DO 0～7（复选框） | 控制输出 |
| DI 0～7（只读标签） | 显示输入状态 |
| 全部读取（按钮） | 手动刷新 DI/DO |

节点公开 4 个 `Q_PROPERTY`：

| 属性 | 类型 | 说明 |
|------|------|------|
| `host` | QString | 模块 IP（变更即重连） |
| `port` | int | Modbus TCP 端口（变更即重连） |
| `serverId` | int | Modbus 从站 ID |
| `connected` | bool | 连接状态（只读回读，写无效） |

## 4. 外部控制（OSC 地址）

地址前缀：`/dataflow/{别名}/{节点ID}/…`

| 地址 | 方向 | 说明 |
|------|------|------|
| `/host` | 可写（命令） | 字符串，改 IP 并立即重连 |
| `/port` | 可写（命令） | 整型，改端口并立即重连 |
| `/serverId` | 可写（命令） | 整型，改从站 ID |
| `/connect` | 只读 | 连接状态反馈——已订阅但 `setConnected` 为空操作，**外部写被忽略** |
| `/DO0`～`/DO7` | 可写（命令） | 布尔，设置对应 DO；写入后反馈 `/DOx` 当前状态 |
| `/DI0`～`/DI7` | 只读 | 轮询读到 DI 变化时反馈对应状态 |

`/host`/`/port`/`/serverId` 绑定界面控件并订阅 Command；`/DOx`、`/DIx` 仅绑定控件（无 member 属性），DO 订阅 Command、DI 仅作状态推送。

## 5. 行为细节

| 类型 | 地址范围 | 读 | 写 |
|------|----------|----|----|
| DO（线圈） | `0x0000`～`0x0007` | FC `0x01` 读线圈 | FC `0x0F` 写多个线圈 |
| DI（离散输入） | `0x0020`～`0x0027` | FC `0x02` 读离散输入 | 只读 |

- **端口语义**：任一 DO 输入收到布尔即更新本地状态，并把 **8 路 DO 当前状态一次性**以 FC `0x0F` 写入设备。
- **写在途控制**：同一时刻仅一条写在途；收到响应或 **800ms 超时**后才发下一条；写期间的新变化合并为最终快照补发一次。
- **轮询节奏**：内部定时器 **100ms（10Hz，厂家要求指令间隔不低于 100ms）**，仅在已连接、无在途响应、写队列空闲时发起读取；每轮依次读 DI（FC `0x02`）与 DO（FC `0x01`）。
- **连接建立**：TCP 连上后先按当前 DO 设置下发一次，再开始轮询。
- **线程模型**：复用 `TcpClient` 设备层（独立线程收发 + 1s 自动重连），Modbus 帧解析在模型层完成。
- **端口连接策略**：所有输入、输出端口均可连多路（Many/Many）。
- **持久化**：`values.host`、`values.port`、`values.serverId`、`values.doStates`（8 路布尔数组）；加载后恢复并触发重连。

## 6. 使用说明与典型接法

1. 填写模块 IP、端口、从站 ID，连接成功后 DO 可操作。
2. 勾选 DO 或通过输入端口写入 `true`/`false`；任意一路变化时，节点会将 **8 路 DO 当前状态** 一次性写入设备。
3. 从 DI 输出端口读取传感器或按钮状态。
4. **连接建立后**，会先将界面/输入端口中的 DO 设置下发到设备，再开始轮询读取。
5. 连接后自动轮询 DI/DO（100ms 定时器）；写操作进行中时会暂停轮询，避免读写冲突。

## 7. 示例

逻辑节点根据 DI 3 为高 → 向 DO 1 写入 `true` 驱动继电器；DI 3 接条件，DO 1 接本节点输入。

## 7. 常见问题（可选）

- 设备固件须支持 **FC `0x0F`（写多个线圈）**；若不支持，写操作会失败。
- 批量写只保证 **最终状态** 一致；极短时间内同一路 `true → false` 等中间翻转可能被合并，硬件上不一定出现短脉冲。
- 多路 DO 同时变化时，只需 **一条** Modbus 写命令，比逐路单线圈写更稳定。

**通信行为说明**
两个节点共用同一套写读策略：

### 写 DO

- 触发来源：输入端口、界面复选框、OSC `/DOx` 命令。
- 每次触发更新本地 `_outputStates` 后，调用 **写多个线圈（FC `0x0F`）**，将当前全部 DO 状态一次下发。
- **同一时刻仅允许一条写在途**；收到设备响应（或 800ms 超时重试）后才发下一条。
- 写期间若又有新变化，会在当前写完成后 **补发一次** 最新全部 DO 状态（合并中间变化，只保留最终快照）。

### 读 DI / DO

- 内部定时器 **100ms（10Hz，厂家要求指令间隔不低于 100ms）**，仅在已连接、无在途响应、写队列空闲时发起读取；也可点击「全部读取」手动触发。
- 每次轮询依次读取 DI（FC `0x02`）与 DO（FC `0x01`）。
- 写操作进行中时跳过轮询；读 DO 时不会覆盖正在下发的 DO 状态。

### 连接建立

1. TCP 连接成功。
2. **先写**：将当前 DO 设置（界面/输入端口中的值）同步到设备。
3. **再读**：开始轮询 DI/DO 状态。
