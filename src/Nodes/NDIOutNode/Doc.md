# NDI Out

## 1. 节点说明

> ⚠️ **版本要求**：本节点为 **Advance（进阶版）** 功能，需有效授权后才能加载使用。

将图像以 NDI 流形式发送到网络，供 vMix、OBS、其他 NDI 接收端使用。

## 2. 端口说明

| 方向 | 默认数量 | 可编辑 | 最小 | 最大 | 新增端口类型 | 末端口差异 |
|------|----------|--------|------|------|--------------|------------|
| 输入 | 2 | 否 | 2 | 2 | — | 无 |
| 输出 | 0 | 否 | 0 | 0 | — | 无 |

> 本表对应 .flow 中该节点的 `input-count` / `output-count` / `port-editable` 三个字段：
> AI 搭图时连接索引不能超过当前端口数，可编辑节点的取值范围由"最小/最大"给出。



### 输入

- **IMAGE**（ImageData）：要发送的视频帧。
- **ENABLE**（VariableData）：是否发送（布尔）。

### 输出

无输出端口。

## 3. 界面与属性

本节点不提供节点体内嵌控件（`embeddedWidget()` 已停用）；发送名称与启停通过**属性面板**或外部控制设置。

可外部控制的属性（Q_PROPERTY）：

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `senderName` | string | `NodeEditor NDI Output` | 接收端可见的 NDI 源名 |
| `enable` | bool | false | 是否发送 |

## 4. 外部控制（OSC 地址）

地址前缀：`/dataflow/{别名}/{节点ID}/…`

| 地址 | 方向 | 说明 |
|------|------|------|
| `/senderName` | 读写 | NDI 源名称（运行中修改会自动重建发送器） |
| `/enable` | 读写 | 启停发送（bool） |

## 5. 行为细节

- **发送线程**：NDI 发送在专用 QThread 中运行，模型侧只缓存帧，UI 不阻塞；停止时等待线程退出（最多 3 s，超时强制终止）。
- **帧时钟驱动**：不逐输入推流——订阅 TimestampGenerator 帧时钟，每个系统 tick 检查输入环形缓冲的最新帧，按时间戳去重（同一帧不重发）后交给发送线程。
- **读回管线**：发送前在 GUI 线程将 ImageFrame 经 `ImageReadback` 读回为 cv::Mat（模型就绪时预热 GPU 上传模块）。
- **格式转换**：1 通道灰度 → BGRA，3 通道 BGR → BGRA，4 通道直接使用；统一按 BGRX FourCC、逐行扫描（progressive）发送，时间码由 NDI 合成，标称帧率 30 fps。
- **改源名**：运行中修改发送名称会先停发再以新名称重建发送器并恢复发送。
- **错误处理**：发送器创建失败或出错时自动停止发送并复位 enable 状态。
- **端口语义**：IMAGE 仅保存输入 ImageData 句柄（新数据到达时重置去重时间戳）；ENABLE 以 `asBool()` 启停。
- **持久化**：`save()` 将 `senderName`、`isSending` 写入**顶层 JSON 键**（非 `values.*`）；`load()` 恢复后按值启停。

## 6. 使用说明与典型接法

1. 填写发送名称（接收端可见的 NDI 源名）。
2. 连接 IMAGE，ENABLE 为 true 时开始推流。
3. 在接收软件中选择对应 NDI 源。

外部地址：`/senderName`、`/enable`。
