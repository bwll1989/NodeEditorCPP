# Ping

## 1. 节点说明

用 ICMP 检测主机是否可达。适用于没有状态回传的设备，作为可访问性指示。Windows 下使用 `IcmpSendEcho`，不依赖 `ping.exe` 子进程。

## 2. 端口说明

| 方向 | 默认数量 | 可编辑 | 最小 | 最大 | 新增端口类型 | 末端口差异 |
|------|----------|--------|------|------|--------------|------------|
| 输入 | 1 | 否 | 1 | 1 | — | 末端口为 ENABLE（启停） |
| 输出 | 1 | 否 | 1 | 1 | — | 无 |

> 本表对应 .flow 中该节点的 `input-count` / `output-count` / `port-editable` 三个字段：
> AI 搭图时连接索引不能超过当前端口数，可编辑节点的取值范围由"最小/最大"给出。



**输入（1）：** ENABLE  
**输出（1）：** CONNECTED

| 端口 | 行为 |
|------|------|
| ENABLE | `true`：立即 ping，之后固定每 **10 秒**；`false`：停止，CONNECTED 置为不可达 |
| CONNECTED | 最近一次 ping 是否成功 |

## 3. 界面与属性

控件面板（`WidgetEmbeddable=false`，显示在右侧属性面板，不嵌入节点体）：

| 控件 | 说明 |
|------|------|
| Host | 目标 IP / 主机名（默认 `127.0.0.1`） |
| 启用 | 与 ENABLE 端口相同：开则每 10s ping，关则停止 |
| 状态 | 可达（绿）/ 不可达（红） |

公开属性：`host`、`enabled` 可写；`connected` 只读（仅有变更信号）。

## 4. 外部控制（OSC 地址）

地址前缀：`/dataflow/{别名}/{节点ID}/…`

| 地址 | 方向 | 说明 |
|------|------|------|
| `/host` | 只读 | 当前目标地址；变化时自动推送反馈。 |
| `/enable` | 只读 | 探测开关状态；变化时自动推送反馈。 |
| `/connected` | 只读 | 最近一次探测结果；变化时自动推送反馈。 |

三个地址均注册了带属性 member 的绑定：模型就绪时各推送一次初始值，此后属性每次变化自动推送。但源码未实现 `onGlobalEvent`、也没有订阅任何 Command 地址——**外部对这三个地址写入均无效**，启停与改 host 只能通过界面或 ENABLE 端口。

## 5. 行为细节

- **Windows**：进程内 `IcmpSendEcho`（`iphlpapi`），超时 3s，不启动 `ping.exe`
- **Linux/macOS**：系统 `ping -c 1 -W 3 <host>`（子进程，启动失败视为不可达）
- 探测在后台线程执行，不阻塞 UI
- 以收到 ICMP 回复判定可达（仅 IPv4）
- 同一时刻每个节点只运行一次探测；上一次未结束则跳过本次
- 启用瞬间立即探测一次，之后固定每 10s；停用时作废在途探测（generation 计数丢弃过期回调）并把 CONNECTED 置为不可达
- ENABLE 端口断开或收到假值时自动停用；真值解析支持布尔、非 0 整数、字符串 `"true"`/`"1"`
- Windows 下每轮探测直接取界面输入框里的 host 并回写属性（不触发变更信号），修改 host 后下一轮探测生效
- 端口连接策略：输入、输出均为 Many
- 禁用或析构时会作废进行中的探测结果，避免回调竞态
- 工程保存 `host`、`enabled`（`values` 子对象两键；`host` 加载失败回落当前值，`enabled` 键存在才应用）

## 6. 使用说明与典型接法

基本用法：将上游节点输出接入本节点输入端口，本节点输出端口连接下游节点的对应输入。
