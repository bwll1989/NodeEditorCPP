# 安卓播放器 TCP 通信协议

## 1. 概述

| 项目 | 说明 |
|------|------|
| 传输层 | TCP |
| 默认端口 | `9090` |
| 编码 | 二进制帧头 + ASCII JSON 载荷 |

---

## 2. 帧格式

```
+--------+-----------+------------------+
| Header | Length    | Payload          |
| 1 byte | 2 bytes   | Length 字节      |
+--------+-----------+------------------+
| 0xA0   | 大端无符号 | 见下文           |
+--------+-----------+------------------+
```

| 字段 | 长度 | 说明 |
|------|------|------|
| Header | 1 | 固定 `0xA0` |
| Length | 2 | Payload 字节数，**大端（Big-Endian）** |
| Payload | N | ASCII：以字符 `'1'`（`0x31`）开头，后接 JSON |

### Payload

```
'1' + JSON
```

JSON 字段均为字符串：

| 字段 | 含义 |
|------|------|
| `tp` | 类型 |
| `com` | 命令码 |
| `pm` | 参数 |

示例：

```json
{"tp":"1","com":"10","pm":"10"}
```

### 组包规则

```
payload = "1" + json_encode({ tp, com, pm })
frame   = 0xA0 + be16(len(payload)) + payload
```

---

## 3. 命令

当前约定：`tp` 固定为 `"1"`。

| 命令 | com | pm | 说明 |
|------|-----|-----|------|
| 握手 / 保活 | `"9"` | `""` | 空参数 |
| 播放 | `"10"` | `"10"` | |
| 停止 | `"10"` | `"17"` | 与播放同属 `com=10`，由 `pm` 区分 |

## 5. 回包特征（从收包样本归纳）

回包同样为二进制流。已知可区分类型与设备信息的字节特征如下（字节序号从 1 起）：

| 用途 | 字节位置 | 特征值 | ASCII |
|------|----------|--------|-------|
| 状态类回包标记 | 第 12 字节 | `0x32` | `'2'` |
| 握手类回包标记 | 第 27–28 字节 | `0x6E 0x61` | `"na"` |
| 设备 ID | 第 32 字节起 | ASCII 数字 | 一位 ID 时其后可为 `'"'`（`0x22`）；两位 ID 时连续两字节均为数字 |
| 播放中 | 第 12 字节为 `'2'`，且第 34 字节为 `0x30` | `'0'` | |
| 已停止 | 第 12 字节为 `'2'`，且第 34 字节为 `0x32` | `'2'` | |

> 完整回包 JSON 字段定义待补充；上表仅描述可观测特征。

---

## 6. 约束

1. `Length` 必须等于 Payload 实际字节数。
2. JSON 中 `tp` / `com` / `pm` 均为字符串，不是数字。
3. 播放与停止共用 `com="10"`，务必用 `pm` 区分。

---

## 7. 测试用十六进制指令

> 下列帧均可直接用 TCP 工具往 `9090` 端口收发验证。字节序号从 1 起，与第 5 节一致。

### 7.1 播放器发送（客户端 → 控制端）

#### 客户端握手信号

特征：第 27–28 字节为 `na`，第 32 字节起为 ASCII 设备 ID（下例 ID=`1`）。

**Payload（ASCII）**

```
2{"tp":"1","com":"09","na":"1"}
```

**十六进制**

```
A0 00 1F 32 7B 22 74 70 22 3A 22 31 22 2C 22 63 6F 6D 22 3A 22 30 39 22 2C 22 6E 61 22 3A 22 31 22 7D
```

| 段 | 值 |
|----|-----|
| Header | `A0` |
| Length | `00 1F`（31） |
| Payload | `2{"tp":"1","com":"09","na":"1"}` |

两位 ID 示例（ID=`12`，第 32–33 字节为 `1` `2`）：

```
A0 00 20 32 7B 22 74 70 22 3A 22 31 22 2C 22 63 6F 6D 22 3A 22 30 39 22 2C 22 6E 61 22 3A 22 31 32 22 7D
```

#### 客户端播放信号

特征：第 12 字节为 `'2'`（`0x32`），第 34 字节为 `'0'`（`0x30`）表示播放中。

**Payload（ASCII）**

```
2{"tp":"2","com":"10","stat":"0"}
```

**十六进制**

```
A0 00 21 32 7B 22 74 70 22 3A 22 32 22 2C 22 63 6F 6D 22 3A 22 31 30 22 2C 22 73 74 61 74 22 3A 22 30 22 7D
A0 00 1C 31 7B 22 74 70 22 3A 22 31 22 2C 22 63 6F 6D 22 3A 22 39 22 2C 22 70 6D 22 3A 22 22 7D
```

| 段 | 值 |
|----|-----|
| Header | `A0` |
| Length | `00 21`（33） |
| Payload | `2{"tp":"2","com":"10","stat":"0"}` |

#### 客户端停止信号（对照）

第 34 字节改为 `'2'`（`0x32`）表示已停止：

```
A0 00 21 32 7B 22 74 70 22 3A 22 32 22 2C 22 63 6F 6D 22 3A 22 31 30 22 2C 22 73 74 61 74 22 3A 22 32 22 7D
```

> 回包 JSON 字段名以实机为准；测试时只要偏移特征满足第 5 节即可被控制端识别。
